# Draw Talqi on the empty queue as the emblem in text cells

Decided by the user on 2026-10-15 after comparing text-art renders, and
reviewed adversarially (two reviewers). The empty queue stops showing the
painted mascot picture (no image protocol, no half-block picture, no
awake/asleep). It shows the terminal emblem
(`assets/emblem/talqi-terminal.svg`) as a fixed 44×22 block of text
cells: with colours each cell is a glyph with 24-bit foreground and
background; under `NO_COLOR` it is the outline without any colour. Terminals
asqr recognises as drawing sextants natively get sextant glyphs, all
others a quadrant-block fallback. No user override.

## Decisions (user, 2026-10-15)

- Only the standard terminal emblem, no awake/asleep distinction.
- Fixed size 44×22. The emblem needs a main area of 26 rows (22, a blank
  row, the sentence's 3 rows) and 44 columns, so a terminal of at least
  32 rows; below that the sentence stands alone. Today the picture shows
  from 18 rows; the user accepts that 80×24 shows no Talqi. Spec 7.1 and
  the CHANGELOG say so plainly.
- Glyph sets as chafa makes them: `sextant` (sextants plus `█▌▐`) and
  `quad` (quadrants plus `▀▄█▌▐`). asqr assumes narrow width for East
  Asian Ambiguous characters throughout (it already draws `─│╭━↑←…·▀`);
  the ADR states that.
- No override.

## Templates and generator

- Four templates in `src/tui/render/mascot/`: sextant colour, quadrant
  colour, sextant outline, quadrant outline.
- Generated by a committed Python script with PEP 723 inline metadata
  pinning its dependencies (run with `uv run`), not a shell script: the
  outline needs a mask pipeline (crop to alpha > 8, LANCZOS resize,
  2nd/98th percentile stretch inside the figure, threshold below 0.30,
  OR a Sobel edge of the blurred alpha, blur 1.2), as in the logbook's
  `ascii/gen.py` and `ascii/nocolour.py`.
- Sources committed under `assets/emblem/`: `talqi-terminal.svg` for the
  colour templates, and a hollow-bar variant (the terminal bar drawn as an
  outlined box with the prompt inside, today only in the logbook as
  `ascii/src/talqi-emblem-wake-hollow.svg`) for the outlines.
- chafa 1.18.2 commands, recorded in the ADR:
  - colour: `chafa --format symbols --colors full --symbols {sextant|quad}
    --size 44x22 --work 9 --dither none --polite=on --bg '#09171a'`
    (`--polite=on` drops the `ESC[?25l/h` around the output; `--bg` makes
    edge pixels blend into the emblem's body colour instead of black,
    which would leave a dark rim on light themes);
  - outline: `--colors none` from the mask picture, white on black, with
    `--fg white --bg black`, same sets and size, `--polite=on`.
- The generator asserts for real that the outline files contain no ESC.
  chafa's output is deterministic (three runs and 1/4 threads gave the same
  hash).

## Parsing and drawing

- The colour templates contain, besides glyphs: SGR `0`, `7` (reverse,
  followed by a foreground-only colour, 7 cells in the sextant template),
  `38;2;r;g;b`, `48;2;r;g;b`, and both combined in one SGR. Colours carry
  over from cell to cell (chafa writes a colour only when it changes);
  every line ends in `ESC[0m`.
- A small stateful SGR interpreter over 0, 7, 38;2, 48;2, 39, 49 (also
  combined) turns a template into cells (symbol, fg, bg, reversed) and
  fails on any other parameter; a test over every embedded file pins that.
  Parse once, lazily.
- Drawing rule: skip only a space with default background that is not
  reversed (the foreground of such a cell is noise); otherwise set the
  symbol, set fg if it has one, set bg only if it has one, add
  `Modifier::REVERSED` if reversed (or swap fg/bg at parse time). Outline
  cells are drawn with no style at all.
- Transparent cells show the terminal background in both themes.

## Choosing the glyph set

- Two pure functions, decided once at startup:
  - `from_env(vars)`, used only when `TMUX` is unset or empty. Rules
    (versions from the research): Ghostty (`TERM_PROGRAM=ghostty`, or
    `TERM=xterm-ghostty`, which crosses ssh), kitty (`TERM=xterm-kitty`
    or `KITTY_WINDOW_ID`), WezTerm (`TERM_PROGRAM=WezTerm`,
    `TERM_PROGRAM_VERSION` ≥ `20210814` as a date prefix), iTerm2
    (`TERM_PROGRAM=iTerm.app` or `LC_TERMINAL=iTerm2`, version ≥ 3.6.7),
    foot (`TERM` starting with `foot`), VTE (`VTE_VERSION` ≥ 6000),
    Konsole (`KONSOLE_VERSION` ≥ 220400), Alacritty (`TERM=alacritty`
    or `ALACRITTY_WINDOW_ID`, no version available), Rio
    (`TERM_PROGRAM=rio`, ≥ 0.4.6), Contour (`TERMINAL_NAME=contour`).
    `TERM_PROGRAM` decides before the `*_WINDOW_ID` variables. A version
    parser per terminal (numeric prefix; a pre-release counts as its
    release, e.g. `3.6.7beta2`); an unparsable version gives the fallback,
    except for kitty and Alacritty, which carry none.
  - `from_xtversion(text)` for tmux: the outer terminal's XTVERSION
    string from `#{client_termtype}`, with its own prefix and version
    table (`kitty(`, `foot(`, `WezTerm `, `ghostty `, `iTerm2 `, `VTE(`,
    `Konsole `, `contour `, `Rio `); empty or unknown gives the fallback.
- Inside tmux, the outer environment variables are stale and are not
  used. `#{client_termtype}` is added to the existing `display-message`
  query in `src/terminal.rs` (today `#{allow-passthrough}
  #{session_attached}`), with tab separators since the termtype contains
  blanks, run once at startup regardless of the image path and handed to
  both users. No extra process; a failure gives the fallback.
- `TERM` starting with `screen` without `TMUX`, or a set `ZELLIJ`: the
  terminal cannot be asked, fallback.
- ADR records: multi-client tmux answers for the current client; nested
  tmux falls back; ssh into a remote tmux from Ghostty is recognised.

## Docs

- A new ADR superseding ADR 39 (picture, protocols, half blocks,
  awake/asleep) and ADR 41 (braille), recording the decision, the four
  templates and their generator with the exact commands and chafa 1.18.2,
  the allowlist with sources, the fallback, the ambiguous-width
  assumption, the size rule, the tmux/screen/zellij handling, and that
  inside tmux without RGB support the 24-bit colours are mapped to 256
  colours. The `NO_COLOR` wording is "no colour sequence": the outline's
  cells have no style, and under `NO_COLOR` no SGR with a colour other
  than the defaults reaches the terminal; ADR 41's "without any escape
  sequence" is corrected the same way.
- Spec 7.1, 7.7 (lines about Talqi's pictures), 8, the section 12 table
  (Talqi's pictures built into the executable); design guide exception
  paragraph; CHANGELOG (the unreleased Talqi entries rewritten, the
  32-row floor stated).

## Tests (first, red shown)

- Template shape: 22 rows of 44 cells each; outlines ESC-free.
- The SGR interpreter over every embedded file; unknown parameters fail.
- Drawing: a transparent space with a foreground leaves the buffer cell
  untouched; a glyph over default background keeps the buffer's
  background; a reversed cell gets REVERSED; outline cells have the
  default style.
- Glyph-set choice per environment: each allowlist entry, each version
  floor's edge, pre-releases, unparsable versions, `TERM=xterm-ghostty`,
  precedence of `TERM_PROGRAM` over `KITTY_WINDOW_ID`, `TMUX` set with a
  stale `KITTY_WINDOW_ID` (fallback), each XTVERSION prefix, an empty
  termtype, a termtype with blanks through the tab-separated query,
  screen and zellij.
- The size rule: 31 rows show the sentence alone, 32 rows the emblem.
- `NO_COLOR`: no colour anywhere in the buffer; a PTY test resized to at
  least 32 rows that first asserts an outline glyph is on screen, then
  checks the raw output for `[38;`, `[48;` and the palette codes.
